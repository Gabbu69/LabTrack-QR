# LabTrack QR thesis evaluation package

Scope: one laboratory, three roles, individual QR identification, borrowing and return reconciliation. Project value: PHP 10,000. Use fictional demo records for practice and adviser-approved participants for evaluation.

## Before collecting results

Confirm the research questions, participant selection, sample size and questionnaire with the thesis adviser. Do not describe this worksheet as a validated instrument unless the adviser has approved an appropriate validation process. Explain the task, obtain the consent required by your institution and use participant codes rather than names. Never collect passwords, authenticator codes or setup keys. Keep completed worksheets private.

Use the same device, network and test scenario when comparing runs. Record camera, USB or typed input separately. The existing shared demo is suitable for a supervised demonstration; coordinate one group at a time. Use a disposable hosted test setup for controlled resets and destructive tests. Do not reset operational inventory.

## Run the task worksheet

Open `/thesis-evaluation.html` for a blank, printable two-page A4 worksheet. It has no submission form and sends no evaluation data to a server. Record observed results manually.

Suggested custodian tasks: identify a student, identify a tool, review/confirm checkout, reject a duplicate scan, accept a partial return, accept the remaining return, handle an explicitly missing tool, filter history and print/export the report. Student tasks: show personal QR and check current custody/history. Instructor tasks: inspect records and verify that restricted operations stay unavailable.

Measure:

| Measure | Calculation or recording rule |
| --- | --- |
| Task success | Count tasks completed correctly / tasks attempted; show both counts and percentage |
| Completion time | Seconds from the stated start to visible confirmation; record assistance and failures separately |
| Scan success | Successfully resolved valid codes / valid scan attempts; report input method and device |
| Errors | Count duplicate, wrong-record, unreadable-code, permission or workflow errors separately |
| User feedback | Show distributions or medians of the worksheet's 1–5 ratings, with limitations |

If comparing manual recording with LabTrack, use equivalent prepared scenarios and counterbalance order where feasible. Do not treat faster completion by a trained developer as evidence of improved student usability. State the actual participant count and device/network limitations.
